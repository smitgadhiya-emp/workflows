Every release produces a collection of merged PRs that nobody synthesizes into coherent communication. Developers get raw PR titles, clients get nothing, and management gets whatever the PM remembered to write in a Teams message. This workflow reads all merged PRs since the last release tag, classifies each change as feature, bug fix, performance improvement, breaking change or internal, writes three distinct versions of the release notes - a technical changelog for the dev team, a plain-language user-facing update, and a one-paragraph executive summary - saves all three to Google Drive, posts the appropriate version to the relevant channel, and updates the changelog file in the repo. Every release gets communicated to the right audience in the right language.
