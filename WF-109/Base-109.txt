"Business Problem

Before implementing a new backend feature, developers spend significant time understanding the existing system.

Typical questions include:

Which APIs need to be added or modified?
Which database tables are affected?
Do existing migrations conflict?
Which services and repositories need updates?
Will this change break existing APIs?
Which modules depend on these models?
Which validations and permissions are required?
What tests need updating?

This investigation is repeated by every developer, leading to duplicated effort and missed impacts.

This workflow automatically analyzes the codebase and produces a complete implementation blueprint before any code is written.

To evaluate true senior backend engineering skills, add these capabilities:

Dependency Graph Analysis: Trace all downstream services, jobs, events, repositories, and APIs affected by the proposed changes to identify hidden impact areas.
Backward Compatibility Check: Detect whether database or API changes could break existing clients, integrations, or mobile app versions, and recommend versioning or migration strategies.
Performance Impact Prediction: Analyze query patterns and relationships to predict N+1 issues, missing indexes, expensive joins, cache invalidation needs, and transaction bottlenecks before implementation.
Security Review: Identify new authorization rules, permission updates, sensitive data exposure risks, audit logging requirements, and input validation gaps introduced by the feature.
Effort Breakdown: Produce a development plan with estimated effort for schema changes, business logic, API implementation, testing, documentation, and deployment, helping the tech lead plan the sprint.
Release & Rollback Strategy: Recommend deployment order (migrations, backend rollout, feature flags, frontend dependency), rollback steps, and data migration precautions to minimize production risk."
