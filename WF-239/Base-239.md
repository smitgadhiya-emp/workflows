Extracts the CORS allowed-origins configuration from all Express middleware, Next.js API route headers, and Nginx configuration files across the codebase. Cross-references the configured origin whitelist against actual production HTTP request logs to identify three gap types: origins in the whitelist that never appear in traffic (dead entries that could be compromised and abused), production origins missing from the whitelist that are being silently blocked (causing user-facing failures), and wildcard * policies on routes that handle authenticated requests. Detects the split-configuration problem where cors() middleware is applied globally but individual route handlers override it with less restrictive settings, bypassing the global policy. Verifies that CORS preflight OPTIONS handling returns consistent allowed-methods lists that match the actual methods implemented on each route. Calculates the gap between the intended policy and the actual effective policy per route and export the audit to Google Sheets with origin, route, configured policy, effective policy, and traffic presence per combination.
