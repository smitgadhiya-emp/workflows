I want the hard version of this. If two people ran this on the same repo and the same question log, they should land on the same version tags, the same verdicts, and the same gaps. Here is the part where most attempts at this get lazy: documentation pages usually do not say which version they describe. The page just says "current." So a version tag is a claim, and I want every claim backed by evidence, a changelog entry, a release note, a versioned docs URL, something a reader can follow. If you cannot establish which versions a page applies to, tag it version-unverified rather than guessing, and treat anything built on it accordingly. Stack Overflow needs the same skepticism: an accepted answer from 2019 with four thousand upvotes can be flat wrong for our versions, so date it and version-check it before it earns a place in the corpus, and record why you trusted it.

Entries that touch each other across technologies should link both ways, an Express session entry that depends on a Node crypto behavior points at it and vice versa, because a corpus of isolated pages is just bookmarks. When two versions of the same docs genuinely disagree, like MongoDB 5.x and 7.x describing aggregation behavior differently, do not pick a winner.
